# F2.1 — Banco di confronto della migrazione del c.a.

Passo F2.1 del [piano](piano.md): prima di sostituire il legacy c.a. di `X.Calculations` con
`GPCChecker.Concrete` (F2.5-F2.9) serve un riferimento del legacy attuale, una mappa delle API e
un confronto ripetibile. Nessun codice di produzione cambia in questo passo. La mappa delle API è
in [f2-matrice-api.md](f2-matrice-api.md).

## Componenti

| Componente | Dove | Cosa fa |
| --- | --- | --- |
| Cattura densa | `supporto/test/CheckerMigration.Capture` | griglie dense dei nuclei legacy (README dello strumento) |
| Script di cattura | `tools/banco/Invoke-DenseCapture.ps1` | compila lo strumento e cattura `tutte`, `muri`, `pali`, `mesh` con `--manifest` |
| Comparatore | `ANTHEA.Testing compare-dense` (`tests/ANTHEA.Testing/Comparison/DenseComparer.cs`) | confronto file per file con tolleranze e classificazione (README del toolkit) |
| Classificazione | `tests/ANTHEA.Testing/f2-classificazione.json` | confronti `fixture-checker`, `b0`, `pre-m4`: file, SHA-256 delle fixture, identificativi casuali, differenze attese (nessuna per `fixture-checker` e `pre-m4` dal 7/10) |
| Tolleranze | `tests/ANTHEA.Testing/tolerances.json`, grandezze `ca_fixture_*` | allineate ai MigrationTests di Checker; i confronti fra catture ANTHEA sono esatti |
| Runner | `build/ci.ps1`, stadio `baseline` | suite `baseline/banco-ca` (fixture) e, con `-DenseRef`, `baseline/banco-denso` |

## Come rieseguire

Dalla radice del repository (o del worktree):

```powershell
# catture dense (circa 2 minuti per corsa); -NoBuild per riusare il binario
powershell -NoProfile -ExecutionPolicy Bypass -File tools\banco\Invoke-DenseCapture.ps1 -Output <F2-pre-m4-v2>\a
powershell -NoProfile -ExecutionPolicy Bypass -File tools\banco\Invoke-DenseCapture.ps1 -Output <F2-pre-m4-v2>\b -NoBuild

# comparatore
dotnet build tests\ANTHEA.Testing\ANTHEA.Testing.csproj -c Release
$t = 'tests\ANTHEA.Testing\bin\Release\net8.0\ANTHEA.Testing.dll'
dotnet $t compare-dense <Checker>\GPCChecker.Test.Concrete\Fixtures <F2-pre-m4-v2>\a\tutte --confronto fixture-checker --report fixture.json
dotnet $t compare-dense <F2-pre-m4-v2>\a\<modalità> <F2-pre-m4-v2>\b\<modalità> --confronto pre-m4 --report doppia.json
dotnet $t compare-dense <F0-B0>\dense\<modalità> <F2-pre-m4-v2>\a\<modalità> --confronto b0 --report b0.json

# runner: solo il banco, oppure tutto il profilo baseline
powershell -NoProfile -ExecutionPolicy Bypass -File build\ci.ps1 -Profile baseline -Only '^baseline/banco' -DenseRef <F2-pre-m4-v2>\a\tutte
```

`<F2-pre-m4-v2>` è `supporto/artefatti/baseline/F2-pre-m4-v2` del repository principale (riferimento denso
dal 7/10/2026, vedi [Nuova fotografia](#nuova-fotografia-del-7102026-f2-pre-m4-v2)), `<F0-B0>` è
`supporto/artefatti/baseline/F0-B0`. La prima cattura di F2.1, `supporto/artefatti/baseline/F2-pre-m4`,
resta come storico. In un worktree il runner trova le fixture di Checker accanto
all'albero principale; altrimenti si passa `-CheckerFixtures`. Le uscite del runner vanno in
`supporto/artefatti/ci/` (o in `-Output`).

## Tolleranze

Le grandezze `ca_fixture_*` di `tolerances.json` hanno `abs = rel = t`, con `t` dei MigrationTests:
1e-9 (taglio, SLE, torsione, fessurazione, ancoraggi, dettagli), 1e-7 (M-χ), 1e-12 assoluto
(copriferri). Il criterio del toolkit `|a − b| ≤ abs + rel · max(|a|, |b|)` contiene quello dei test,
`t · max(1, |atteso|)`, ed è al più il doppio. Per le deformazioni dei punti snervati della curva
M-χ il banco resta a 1e-7 (i test usano 1e-3 per la riconvergenza della libreria). Ingressi, testi,
esiti e celle senza regola sono esatti, come ogni confronto fra catture ANTHEA (`denso/`).
